# 一花交通 バス案内

架空のバス会社「一花交通」の時刻表・乗換案内・バス走行位置を見られるWebアプリです。
ビルド不要の静的ファイルだけで動くので、GitHub Pages でそのまま公開できます。

## できること

### 一般向け

- **停留所時刻表**：停留所を選ぶと、時刻表を「時」と「分」の形で表示します。路線・方面ごとに絞り込めます。運休が決まった便には「運休」と表示します。
- **停留所検索**：停留所名の一部から検索し、路線・方面ごとの先発・次発（遅れつき）、本日の始発〜最終、近づいているバス（何停留所前か・到着までの目安・遅れ・車番）、まもなく発車する便、周辺の地図を確認できます。
- **便の停車停留所**：時刻表の時刻を押すと、その便が停車する停留所・時刻・乗車停留所からの運賃（大人／小児）を表示します。
- **乗換案内**：出発・到着の停留所と時刻から、早く着く経路を最大5件表示します（乗換時間の指定、区間ごとの運賃合計つき）。「初発」「終車」でも検索でき、運休が決まった便は使いません。
- **路線ごと**：路線を選ぶと、停留所の並びに沿って上下それぞれのバスの位置・遅れ・車番を一覧で表示します（路線は系統番号の若い順）。
- **走行位置**：いま走っているバスを路線図の上に表示します。時間帯に応じた確率で区間の走行に時間がかかり、遅延が発生します。「時刻を指定」で別の時刻や倍速の様子も見られます。
- **車番の確認**：地図や一覧でバスを選ぶと車番と車両情報を表示します。車番を入力して、その車両がいまどこを走っているかも探せます。

ダイヤは日付によって切り替わります。土曜・日曜・祝日（振替休日・国民の休日を含む）と年末年始（12/30〜1/3）は土休日ダイヤ、それ以外は平日ダイヤです。案内データの `notOperating`（`weekend`＝土休日運休、`weekday`＝平日運休）や、曜日別の `day`（`wd`/`sa`/`ho`）に対応しています。

### 事業者向け（8桁のパスワードが必要）

- **車両**：車番・登録番号・メーカー・車種・年式・所属営業所・定員・設備・状態の登録と編集。ランダム追加も可能です。
  - ランダム追加では、車番を「空いている番号からランダム」か「空いている番号を小さい順に」で選べます。追加した車両に、担当車を持っていない乗務員を1台につき1人ずつ割り当てることもできます。
- **テンプレートから登録**：車種テンプレートを選び、車番（漢字1文字＋数字3桁、例：花123）を入れるだけで登録できます。複数台をまとめて入力できます。
  - 年式は、そのテンプレートの製造開始年〜製造終了年の中からランダムに決めます（今年より先の年式は使いません）。
  - 登録番号（ナンバー）は、年式とナンバーの地域から自動で付けます。
- **登録番号（ナンバー）**：1999年までの年式は「地域＋22あ」、2000年以降は「地域＋200か」です。
  - `templates.js` のナンバー表で、地域・年ごとの番号の範囲を決めています。範囲は「その年の開始番号〜翌年の開始番号の1つ前」、1999年は「22ナンバー終了」の行の番号までです。
  - 範囲の中から、ほかの車両と同じ番号にならないようにランダムに付けます。「ナンバーを付け直す」で、空欄・範囲外・重複の車両をまとめて直せます。
  - 表の最後の年（2028年）は翌年の行がないため、前年の件数から終わりの番号を推定しています。
- **乗務員**：氏名・性別・生年月日・所属・入社日・運転技術・接客態度の登録と編集。人数を指定してランダムに登録できます。
  - 年齢は19〜90歳（範囲は指定可）で、40〜50代が多い分布です。
  - 男女比は 6:4 〜 7:3 の範囲で指定できます（初期値 65:35）。
  - 氏名は約1,000種類の姓と約1,000種類の名（男女別）から組み合わせ、同姓同名ができるだけ出ないようにしています。
- **担当車制度**：車両ごとに担当乗務員を紐づけられます（自動割り当てもあり）。担当者は日替わりでその車両に乗務します。
- **運用表**：車両の運用（行路）を設定し、日ごとの車両・乗務員・遅延・事故の結果を確認できます。
  - 運用に入っている便だけが運行します。どの運用にも入っていない便は「運用未設定」で運休になり、時刻表などにも運休と表示されます。
  - 運用ごとに便の追加・取り外し、運用名・所属の変更、運用の追加・削除ができます。つながりに無理がある運用（前の便の到着に間に合わない、停留所が違う）には「要確認」と表示します。
  - 案内データに運用（duties）があればそれを使います。案内データの運用が更新されると、次に開いたときに自動で取り込みます（臨時運用は残ります）。運用がない案内データでは時刻表から自動で作ります。
  - 車両は、出庫から入庫までの時間が重ならなければ1日に複数の運用に入ります。乗務員は1人1日1運用です。運用表の「足りない車両・乗務員を追加」で、その日の運用に足りない分をまとめて追加できます。「運用未設定の便から運用を作る」「運用を作り直す」も使えます。
  - 臨時便を追加するときは、臨時運用を自動で作るか、運用に入れない（あとで設定）かを選べます。
- **臨時便**：運行日・系統・区間・発車時刻・本数・間隔を指定して追加できます。時刻表・乗換案内・走行位置に反映されます。
- **設定**：遅延の起こりやすさ、パスワード変更、データの書き出し・読み込み、案内データの差し替え。

### 乗務員の能力と運行への影響

| 項目 | 低いとき | 高いとき |
|---|---|---|
| 運転技術（1〜5） | 事故による運転打ち切りが起きやすい（技術3の6倍まで） | 遅延が起きにくく、遅れを取り戻しやすい |
| 接客態度（1〜5） | 乗客とのトラブルで停留所の発車が遅れやすい | トラブルによる遅延が減る |

遅延・トラブル・事故は「日付＋便」ごとに決まった乱数で計算するので、同じ日に何度開いても同じ結果になります。

### 遅れの目安と続行運転

- 基準停（時間調整を行う停留所）の前後の区間で、1便あたり時間帯ごとの目安まで遅れが広がります。初期値は、日中 3.5〜5.5分、朝夕のラッシュ 10〜20分、夜 1〜3分、早朝・深夜 0〜0.5分です（設定で変更可）。すでに前の便から遅れを引き継いでいるときは、そのぶん上乗せしません。
- 後ろのバスが遅れた前のバスに追いついたときは追い越さず、続いて走ります（続行運転）。同じ区間では前のバスより先に着かず、遅れて停車中の前のバスがいればその発車を待ちます。
- 滞泊する運用（案内データの `overnightStay` と `nextDayTrips`）は、翌朝の便を同じ車両・乗務員が続けて運行します。中間解放のある運用では、解放中の車両をほかの運用に使えます。

### 運休と代走

- 1人の乗務員が受け持つのは1日1運用までです（営業所をまたいで担当が設定されていても重複させません）。
- 運用に入っていない便は運休です。担当乗務員のいる車両から順に運用に入り、その日の担当者が乗務します。担当のいない車両には、その日に乗務のない乗務員（予備の乗務員）が乗ります。
- 車両が足りない運用、乗務員が足りない運用は、その日すべての便が運休になります（前もって分かるので、時刻表や乗換案内に最初から反映されます）。
- 事故が起きると、その車両の次の便は運休です。以降の便は、車庫にいる担当なしの車両と予備の乗務員、それもないときはその日に運用のない乗務員が自分の担当車で代走します。事故の後、出庫準備（初期値10分）と車庫からの回送時間が、その便の発車時刻に間に合わない便は運休です。
- 代走できる担当なしの車両がないときは車両不足、予備の乗務員がいないときは乗務員不足として、その運用の残りの便は運休になります。
- 「担当車を自動で割り当て」は、その日の運用数ぶんの車両にだけ担当を付け、残りを担当なしの予備車として残します。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | 画面とデザイン |
| `app.js` | アプリ本体 |
| `config.js` | 会社名・事業者用パスワード（ハッシュ値） |
| `data.js` | 案内用データ（路線・停留所・時刻表・運賃） |
| `names.js` | 乗務員のランダム生成に使う姓・名のリスト |
| `templates.js` | ナンバー表と車種テンプレート（スプレッドシートのCSVを埋め込み） |
| `fleet.js` | 公開用の事業者データ（車両・乗務員・臨時便・設定）。初期状態は `null` |

## GitHub Pages での公開

1. このフォルダの中身をリポジトリのルートに置いてコミットします。
2. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、ブランチを `main`、フォルダを `/ (root)` にして保存します。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

`index.html` をダブルクリックしてローカルで開いても動きます。

### 更新が反映されないとき

`index.html` は、各JSファイルを毎回サーバーに確認してから読み込みます（変更がなければ通信はわずかです）。そのため、ファイルを更新すればページの再読み込みで新しい内容になります。
GitHub Pages は公開の反映に1〜数分かかります。画面下の「アプリの版」で、どの版が表示されているかを確認できます（`app.js` 先頭の `APP_VERSION` を更新のたびに書き換えると便利です）。
なお、事業者用ページで登録した車両・乗務員・設定などはブラウザに保存されているため、ファイルを更新しても変わりません。初期データからやり直すときは、設定の「初期状態に戻す」を使ってください。

## 事業者用パスワード

- 初期パスワードは **`20261027`** です。公開前に必ず変更してください。
- 事業者用ページ → 設定 → 「パスワードの変更」で新しい8桁を入力すると、そのブラウザでのパスワードが変わり、ハッシュ値が表示されます。
- 公開サイトのパスワードを変えるには、表示されたハッシュ値を `config.js` の `adminPasswordHash` に貼り付けてコミットします。

> **注意**：このアプリはサーバーを持たない静的サイトなので、パスワードはブラウザ側で確認しています。ソースを読めば回避できる「目隠し」程度のものです。架空データのデモとして使い、実在する個人情報は登録しないでください。

## データの保存と公開

- 事業者用ページで登録した内容は、そのブラウザの localStorage に保存されます。ほかの閲覧者には見えません。
- 閲覧者全員に同じ車両・乗務員・臨時便を見せたいときは、設定 → 「公開用 fleet.js を書き出す」でダウンロードしたファイルで `fleet.js` を置き換えてコミットします。
- `fleet.js` が `null` のときは、全員に同じ内容の初期データ（必要な運用数に合わせた車両と乗務員）を自動で作ります。

## ナンバー表・車種テンプレートの更新

スプレッドシートをCSVで書き出し、事業者用ページ → 設定 →「ナンバー表を読み込む」「車種テンプレートを読み込む」で読み込めます（そのブラウザだけに反映）。
公開サイトにも反映するには、読み込んだあと「公開用 fleet.js を書き出す」で作った `fleet.js` をコミットしてください。CSVの中身も一緒に保存されます。

## 案内データの更新

路線や時刻表を作り直したときは、新しく書き出した案内用データ（`busplan-guide` 形式のJSON）で `data.js` を更新します。

```js
window.BUS_GUIDE_DATA = { ...書き出したJSONの中身... };
```

試しに見るだけなら、事業者用ページ → 設定 → 「案内データを差し替える」で、そのブラウザだけ差し替えることもできます。
